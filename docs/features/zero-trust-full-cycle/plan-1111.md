# Issue #1111: PR tracking and verified controller revisions

## Problem
Compose the existing tracker, verified overlay, ledger and fork CAS primitives into explicit observation and revision commands. Ordinary resume must never start implementation. Owner decision #1119 is merged (PR #1121, 28b2696); prose feedback therefore uses typed decisions, with uncertainty handing off. Apply the owner's environmental-corruption/concurrent-legitimate-process threat model from #1109.

## Acceptance Criteria
- [ ] Scenario 13, end to end with edge fakes: a maintainer comment leads to `resume --revise`, a new budget session, a new verified candidate and a CAS push to the same fork branch. The PR head equals the new candidate, and the run is back to `submitted`. The ledger shows two sessions and the first session's spend is unchanged.
- [ ] An out-of-band commit on the fork branch blocks (`push_blocked` / `remote_diverged`), and nothing is overwritten.
- [ ] Feedback already addressed at the current head is not implemented twice: a second `--revise` with no new feedback does nothing.
- [ ] Scenario 16 during revision: an issue closed, or the AI policy banned, before `shipRevision` blocks the push, and the evidence is retained.
- [ ] Merged mid-revision blocks (`merged_during_revision`). Closed mid-revision issues a reopen action and pushes nothing.
- [ ] `withdraw` records `declined` only after the close is observed.

## Approach
1. Observe PR state without automatic revision; carry explicit revise intent into tracking. Persist the tracker-produced run and synchronize every driver after every call.
2. Allocate one durable numbered ledger session for each RevisionRequested transition. Recover crashes between tracker transition, session allocation and controller snapshot; retain all prior reservations/spend. Historical checkpoints validate against their own retained sessions.
3. Classify untrusted feedback through the merged typed decision API. Only confidently in-scope feedback enters implementation; evidence and uncertainty are retained. Provision fresh VMs from the last verified controller-held overlay.
4. Reuse review, verifier, drift, JIT receipt and IntentDriver/ForkPusher CAS on the same branch/PR. Preserve shipping for revision_pending and reuse its immutable candidate.
5. Expose edit/withdraw/cancel-action through locked controller operations and print contributor link/instructions. Never write upstream.
6. Extend real composition tests with edge fakes and local bare forks for all ACs and crash/pause boundaries; run strict build, lint, package coverage and CLI tests.
